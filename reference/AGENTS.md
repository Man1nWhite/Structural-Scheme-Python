# Инструкция для агентов

Проект полностью ведут агенты. Релизов, версий и changelog нет — не создавайте их.

## Что это

Генератор структурных схем АСУ ТП. На выходе — **один файл `index.html`**, который собирается из `src/`
командой `npm run build`: открывается двойным щелчком, работает без интернета и без остальных файлов
репозитория. Язык интерфейса, комментариев и тестов — русский.

## Структура

| Путь | Что внутри |
| --- | --- |
| `index.html` | **Сгенерирован** из `src/shell.html` командой `npm run build`. Руками не править — правки потеряются при следующей сборке. |
| `src/shell.html` | Каркас страницы: подключает стили и скрипты, больше ничего. Источник для сборки. |
| `src/core.js` | Вся логика без DOM: модель проекта, раскладка и трассировка, `toSvg`, `toDrawio`, сохранение/загрузка. |
| `src/app.js` | Интерфейс на React 18 + [htm](https://github.com/developit/htm) (шаблонные строки вместо JSX, Babel не нужен). |
| `src/styles.css` | **Сгенерирован** Tailwind CSS 3 из классов в `src/shell.html` и `src/app.js`. Руками не править. |
| `vendor/` | **Копии** React, ReactDOM и htm из `node_modules`. Руками не править. |
| `tests/` | `node:test`; `app.test.js` — сквозные тесты собранной страницы в jsdom, `routing.test.js` — свойства чертежа. |
| `scripts/` | `build.js` (сборка `index.html`), `vendor.js` (обновить `vendor/`), `serve.js` (локальный сервер). |

## Команды

```bash
npm ci              # один раз: зависимости для тестов и сборки
npm test            # все тесты; должны проходить перед каждым коммитом
npm run build       # пересобрать index.html — обязательный шаг после любой правки src/
npm run build:css   # после добавления/удаления Tailwind-классов
npm run vendor      # после смены версий react/react-dom/htm в package.json
npm start           # сервер на http://localhost:8000/ (0.0.0.0, порт — переменная PORT)
```

## Правила

- **`index.html` — артефакт сборки.** Правьте `src/*`, затем `npm run build`. `tests/repo.test.js` сравнивает
  закоммиченный `index.html` с результатом сборки: если файл устарел, тесты падают.
- **Одна модель — все форматы.** `buildScheme(state)` считает всю геометрию и тексты; `toSvg` (предпросмотр,
  SVG, PNG, JPG) и `toDrawio` только рисуют эту модель. Новый элемент схемы добавляйте в модель и в **оба**
  рендера; `tests/render.test.js` сверяет, что подписи в SVG и Draw.io совпадают.
- **Трассировка восстановлена из пользовательского `index backup.html`.** Точки выхода идут в порядке
  положения целей, входы — в порядке подходов, слоты зазоров распределяются отдельно по уровням,
  с пересчётом после добавления целей. Не возвращайте глобальное резервирование `seat()` без запроса:
  пользователь предпочёл геометрию backup. `tests/backup.test.js` фиксирует опорные маршруты из него.
  Известное ограничение: наложения вертикалей в сложных схемах; три проверки в `tests/routing.test.js`
  сейчас падают. Не удаляйте и не ослабляйте их — они остаются диагностикой ограничения backup.
- **Новое поле проекта или элемента** — добавьте значение по умолчанию в `PROJECT_DEFAULTS` / `ITEM_DEFAULTS`
  в `src/core.js`. Иначе поле не переживёт сохранение и загрузку: `normalizeState` принимает только известные поля.
  Старые сохранения должны открываться; если формат меняется несовместимо, увеличьте `FORMAT_VERSION` и
  добавьте миграцию в `normalizeState`. Значения, влияющие на геометрию, ограничивайте при загрузке
  (`blocksPerRow` → `clampPerRow`), иначе чужие файлы растянут лист.
- **Ссылки между элементами** (`target`, `netTarget`, `rs485Target`) могут указывать на удалённые элементы —
  всегда разрешайте их через `makeResolvers`.
- **Экспорт растровой картинки** ограничен размерами canvas: масштаб считает `rasterScale()`, а `toBlob`
  может вернуть `null` — такой случай обязан показать сообщение, а не молча ничего не сохранить (`src/app.js`).
- **Интерфейс** пишется на htm: `` html`<${Comp} prop=${value}>…<//>` ``. JSX не работает.
- **Без внешних ресурсов**: никаких CDN и `fetch` — `tests/repo.test.js` проверяет, что собранная страница
  не ссылается на внешние файлы и работает офлайн.
- Тесты проверяют поведение (результат `buildScheme`, `toSvg`, `toDrawio`, свойства чертежа, работу страницы),
  а не текст исходников. Исправили ошибку — добавьте тест, который её ловит.
- Изменили поведение или порядок работы — обновите `README.md` (для людей) и этот файл (для агентов).
- Переносы строк — LF (`.gitattributes`).
- CI (`.github/workflows/ci.yml`) запускает `npm ci && npm test` на каждый PR.
