# Для меня: ручные действия владельца проекта

Этот список — действия, требующие вашего компьютера, реальных проектов или
визуальной оценки. Все пункты пока не отмечены. Отмечайте их только после
фактического выполнения.

Последняя подтверждённая локальная проверка в Arena: 46 тестов прошли, включая
14 браузерных сценариев и Hypothesis на 1000 состояниях. Это **не** подтверждение
работы на вашем компьютере, выполнения GitHub CI или проверки в Draw.io.

## 1. Проверить установку на своём компьютере — обязательно

- [ ] Сохранить копии старого генератора и исходных JSON-проектов.
- [ ] Убедиться, что установлен Python 3.11 или новее: `python --version`.
- [ ] В папке репозитория создать виртуальное окружение:

  ```bash
  python -m venv .venv
  ```

  Активировать его:
  - Windows PowerShell: `.venv\Scripts\Activate.ps1`
  - Linux/macOS: `source .venv/bin/activate`

  Если PowerShell запрещает активацию, можно обойтись без изменения политики:
  запускать `.venv\Scripts\python.exe` вместо `python` в следующих командах.

- [ ] Установить приложение: `python -m pip install -e .`.
- [ ] Запустить только для своего компьютера:

  ```bash
  python -m app --host 127.0.0.1
  ```

- [ ] Открыть `http://localhost:8000`, убедиться, что видны четыре русские вкладки
  и схема, а кириллица отображается правильно.
- [ ] Проверить CLI:

  ```bash
  python generate.py examples/demo.json -o out.svg
  ```

  Открыть полученный SVG. Сервер для этой команды не нужен.

## 2. Проверить реальные сложные проекты — самый важный приёмочный шаг

- [ ] Подготовить JSON-файлы самых больших схем, на которых ломался старый
  генератор. Сам HTML старого приложения не является файлом проекта.
- [ ] Открыть каждый файл через **Открыть JSON**. Если проектов несколько,
  начать с самого проблемного.
- [ ] Визуально проверить схему при 100% и 200%: различимы ли параллельные линии,
  понятны ли подходы к блокам, не перекрываются ли подписи и стрелки сигналов.
- [ ] Для плотного проекта проверить 1, 4 и 12 блоков в ряду, KVM-щит,
  RS-485 между шкафами, внешние связи и отображение количества сигналов.
- [ ] Убедиться, что количество и назначения соединений соответствуют проекту,
  а не только что линии выглядят аккуратно.
- [ ] Сохранить копию JSON новым редактором, открыть её заново и убедиться,
  что поля и соединения сохранились.

**Что не считать ошибкой само по себе:** поперечные пересечения горизонтальной
и вертикальной линии разрешены. Полное отсутствие любых пересечений не обещано.
Слияние разных связей по одной прямой или проход через чужой блок — ошибка.
Геометрические тесты также не заменяют оценку читаемости текста.

## 3. Проверить экспорт в своих программах

- [ ] Скачать SVG, PNG, JPG и Draw.io для одного реального плотного проекта.
- [ ] Открыть SVG в браузере/редакторе, PNG и JPG — в обычном просмотрщике.
  Проверить кириллицу, белый фон, подписи и читаемость при увеличении.
- [ ] Открыть `.drawio` в настольном Draw.io / diagrams.net. Проверить, что
  блоки редактируемы и маршруты выглядят как в предпросмотре.
- [ ] Сохранить файл **из Draw.io**, закрыть и открыть повторно. Проверить,
  что Draw.io не перестроил линии неожиданным образом.
- [ ] Если схема пойдёт в документацию, проверить вставку/печать именно
  в используемой вами программе и на нужном размере листа.

Не требуйте от PNG/JPG бесконечного разрешения: растры ограничены 16 млн
пикселей и 16384 px по стороне. Для большого листа используйте SVG или Draw.io.

## 4. Проверить сохранение и работу без интернета

- [ ] Изменить проект, перезагрузить страницу и убедиться, что изменения
  восстановились в том же браузере.
- [ ] Скачать JSON как отдельную резервную копию. localStorage — удобство,
  а не надёжное хранилище: очистка данных браузера может его удалить.
- [ ] После установки зависимостей отключить интернет, оставить локальный
  Python-сервер запущенным и проверить редактирование и все четыре экспорта.
- [ ] Не проверять офлайн-режим выключением самого сервера: браузеру всё ещё
  нужен локальный Python-процесс.

## 5. Сохранить работу в GitHub и проверить CI

- [ ] Просмотреть изменения через `git status` и убедиться, что исходники,
  документация и тесты попадут в коммит, а `.venv`, кэши и личные JSON — нет.
  Автоматическое сохранение Arena не заменяет Git-коммит. Текущее состояние
  проверять через `git status`, `git log` и страницу PR, а не по этому списку.
- [ ] Если нужен коммит/PR, поручить агенту сохранить текущую работу и открыть PR
  либо сделать это самостоятельно. Сессия привязана к ветке
  `arena/45432df8-structural-scheme-python`; не переносить работу другой веткой
  внутри этой сессии.
- [ ] После push открыть GitHub Actions и проверить основные проверки на
  Linux/Windows и отдельный browser job. Не считать наличие YAML-файла
  доказательством успешного CI.
- [ ] При падении browser job скачать артефакт `browser-failures` и передать
  следующему агенту лог ошибки, `failure.png` и `trace.zip`.

## 6. Если обнаружена ошибка — что передать следующему агенту

- [ ] Минимальный воспроизводимый JSON, желательно без конфиденциальных названий.
  Перед отправкой проверить, что обезличенная копия всё ещё воспроизводит ошибку.
- [ ] Версии ОС, Python и браузера, выбранное число блоков в ряду.
- [ ] Точные действия, ожидаемый и фактический результат.
- [ ] Скриншот с отмеченным местом ошибки и экспортированный SVG/Draw.io,
  если проблема относится к экспорту.
- [ ] Для ошибки установки — текст команды и полный вывод ошибки.
  Не отправлять пароли, токены или другие секреты.

## 7. Решения, которые стоит принять после приёмки

- [ ] Определить максимальный реальный размер проекта и допустимое время
  перестроения превью. Это поможет выбрать дальнейшие стресс-тесты.
- [ ] Решить, нужен ли доступ с других компьютеров. Пока приложение рассчитано
  на доверенную локальную среду и не предназначено для публикации в интернете.
- [ ] При необходимости поручить агенту закрепить версии зависимостей и
  проверить обновления на целевых ОС. Текущие зависимости заданы диапазонами,
  не lock-файлом.
- [ ] После проверки отметить выполненные пункты и передать следующему агенту
  оставшиеся проблемы вместе с файлами для воспроизведения.
