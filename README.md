# Структурные схемы АСУ ТП — Python

Локальный редактор и CLI для структурных схем: операторные станции, серверные
стойки, сетевые шкафы, шкафы автоматики, KVM, RS-485 и сигналы DI/DO/AI/AO.
**Python ≥3.11. Node, CDN, Babel, облако и доступ к интернету при работе не нужны.**

Ручные действия владельца перед приёмкой и передачей следующему агенту:
[for me.md](for%20me.md).

## Установка и запуск

```bash
python -m venv .venv
# Linux / macOS:
source .venv/bin/activate
# Windows PowerShell:
# .venv\Scripts\Activate.ps1
python -m pip install -e .
python -m structural_scheme
```

Откройте **http://localhost:8000**. Можно задать `--port 8080` или переменную `PORT`.
По умолчанию сервер слушает `0.0.0.0` (в том числе для preview в Arena).
Для доступа только с вашего компьютера: `python -m structural_scheme --host 127.0.0.1`.
Из репозитория работает и историческая команда `python -m app` (файл-совместимость),
но канонический запуск — `python -m structural_scheme`.
Приложение рассчитано на доверенную локальную среду, не на публичный хостинг.

`pip install -r requirements.txt` — альтернативный способ установки.
Зависимости скачиваются только при установке. После неё редактор и все экспорты
работают без интернета; локальный Python-сервер должен оставаться запущенным.
Растрирование — resvg (готовые Python wheels) и Pillow, без системного Cairo.
Для редкой платформы без wheel может потребоваться Rust при сборке resvg-py.
Для кириллицы должен быть установлен обычный системный шрифт (Arial / DejaVu Sans).

## Редактор

Сохранены четыре русские вкладки и поля исходного `src/app.js`:

- **Проект**: название, подзаголовок, имя файла, блоков в ряду (1–12), названия
  трёх помещений, примечания, отображение количества сигналов.
- **Операторная**: устройства, тип/среда связи/цель, KVM → щит, сам щит и его имя.
- **Серверная**: стойки (серверы, KVM, NTP, ИБП, сетевой шкаф) и сетевые шкафы
  (коммутаторы, МЭ, оптические кроссы, внешняя связь, ИБП).
- **Шкафы автоматики**: контроллеры, uplink, сетевой шкаф, DI/DO/AI/AO и количества,
  RS-485 вниз и между шкафами, выбор второго шкафа.

Предпросмотр SVG перестраивается после редактирования; есть масштаб по ширине,
50/100/200%. **Сохранить проект** скачивает JSON, **Открыть JSON** читает локальный
файл; изменения также сохраняются в localStorage браузера. **Начать заново**
требует подтверждения. Ошибки импорта/сохранения/экспорта видны в редакторе.
Ограничение веб-API: 500 блоков на проект для защиты локального процесса от
случайно слишком большого файла; ядро и CLI этого ограничения не имеют.

Строка состояния под предпросмотром показывает не только размеры листа, но и
предупреждения: слишком длинные подписи обрезаны многоточием (полный текст в
блок не входит), при высоком fan-in шаг портов меньше 2 px (линии могут сливаться),
числовое поле содержит не число или отрицательное значение. Предупреждения не
мешают экспорту: лист строится, но о потере читаемости пользователь узнаёт сразу.
В CLI те же предупреждения печатаются в stderr.

У схемы есть физический предел: на одну грань блока шириной 190 px помещается
около **559** целей (шаг 0.30 px). Дальше линии пришлось бы совместить, поэтому
построение останавливается понятной ошибкой «Недостаточно места для портов
блока», а не молчаливым наложением: превью и экспорт возвращают 422 с этим
текстом, редактор показывает его пользователю, CLI завершается кодом 1.

Кнопки **⬇ SVG / PNG / JPG / Draw.io** экспортируют текущий проект.
PNG/JPG имеют белый фон, обычный масштаб 2× с ограничением 16 млн пикселей
и 16384 px по стороне. SVG/Draw.io не ограничены разрешением.
Draw.io — редактируемые блоки и линии с рассчитанными waypoint-координатами,
без повторной автоматической трассировки в экспортёре.

## Командная строка

```bash
python generate.py examples/demo.json -o out.svg
python generate.py project.json -o out.drawio
python generate.py project.json -o out.png
python generate.py project.json -o out.jpg
```

Формат определяется расширением. Ошибки завершают CLI с ненулевым кодом.
Старые JSON исходного генератора (`structural-scheme`, version 1) принимаются,
как и проекты без заголовка формата. Неизвестные поля отбрасываются,
неподходящие типы заменяются defaults, повторные/пустые ID исправляются,
удалённые цели заменяются первой подходящей. Более новый формат отклоняется.

## Ядро и маршрутизация

```python
from structural_scheme import createDefaultState, buildScheme, to_svg, to_drawio

state = createDefaultState()
state['project']['blocksPerRow'] = 3
model = buildScheme(state)
svg = to_svg(model)
xml = to_drawio(model)
```

Модули: `structural_scheme/constants.py` (константы и defaults), `text_utils.py`
(типы `D`/`TypedDict`, ширина текста и масштаб), `normalize.py` (нормализация и
сериализация JSON v1, резолверы), `routing.py` (интервальная раскраска, реестр
портов `PortRegistry`, раскладка и `buildScheme`), `scheme_core.py` (единый фасад
совместимости), `render.py`, `export.py`, `validation.py`, `app.py` (FastAPI) и
`static/`. Пакет снабжён маркером `py.typed`. Устанавливается ровно один пакет —
`structural_scheme`, поэтому в `site-packages` не появляются общие имена `python`
и `app`. После обновления версии репозитория повторите `python -m pip install -e .`,
чтобы отображение пакета обновилось.

Модель — JSON-совместимые словари: `width`, `height`, `rooms`, `blocks`, `conns`,
`ext`, `signals`, `legend`, `notes`, `warnings` (список предупреждений для
пользователя, до `MAX_WARNINGS` + итог) плюс заголовки и имя файла. API оригинала
(`normalizeState`, `parseState`, `serializeState`, `makeResolvers`, `routeBand`,
`rasterScale`, фабрики элементов) сохранён; доступны и snake_case-алиасы
основных функций. Константы и defaults перенесены из `core.js`.

Это перенос модели и функций, **не пиксельная копия ошибочных маршрутов**:

1. Сохранены уровни op/srv/auto, общие колонки, межрядные полосы, C1/C2,
   обходы по межколоночным зазорам и above-граф `routeBand` из backup.
2. Входы, выходы и сигналы одной грани получают порты совместно. Выходы
   сохраняют порядок целей; высокий fan-in сжимает шаг, не выталкивая порт из блока.
3. `gapRuns` — интервалы по вертикали, включая коридоры. Для совпадающих
   физических зазоров уровней интервалы объединяются. Назначение слотов —
   **точное раскрашивание интервального графа**: sweep-line с очередью окончаний,
   число слотов равно максимальному количеству одновременно активных интервалов.
   Это не жадная сортировка по длине, OR-Tools/SciPy здесь не нужны.
4. Реестр вертикальных интервалов исключает конфликты с портами и смещёнными
   сетками. Непересекающиеся интервалы переиспользуют X; обычный шаг обходов 7 px.
   При ограниченном пространстве портов допускается меньший шаг; ниже 2 px
   в модель попадает предупреждение (позиция порта всё равно не выходит из блока).
   Поиск свободной координаты идёт от ближайшей позиции в обе стороны, а реестр
   отсортирован по X: окно читается через bisect, поэтому раскладка не
   пересканирует все занятые координаты на каждый порт.
5. Зазор между колонками ищется как неподвижная точка: требование при узком
   зазоре завышено сдвинутыми обходами, поэтому после стабилизации зазор
   возвращается к фактически необходимому (плотный проект на 500 блоков даёт
   лист ~7370 px вместо ~24029 px). Превью и экспорты используют одну и ту же
   итоговую геометрию.
6. Подписи блоков обрезаются по ширине блока (`fitText`), как `fit(name, 28)` в
   `core.js`; число сокращённых подписей попадает в `model['warnings']`.
   Без обрезки длинное имя выходило за рамку и наезжало на соседний блок.

Порядок величины на пределе веб-API (500 блоков, плотный проект): превью ≈1 с,
SVG и Draw.io ≈1 с, PNG ≈3.7 с (основное время — растрирование 16 млн пикселей),
четыре одновременных превью ≈4 с суммарно. Медленнее становится только растр:
векторные форматы ограничены раскладкой, а она не пересканирует реестр портов.

Оптимальность гарантируется **для интервального распределения выбранных зазоров**,
не для всей ортогональной трассировки в целом. Поперечные пересечения допустимы
(как в исходных tests/helpers.js); гарантия полной планарности не заявляется.

## Проверки

```bash
python -m pip install -e ".[test]"
python -m pytest -q -m "not browser"
```

Статические проверки и покрытие (extra `[lint]` — ruff и mypy):

```bash
python -m pip install -e ".[test,lint]"
python -m mypy                      # проверяются и тела функций без аннотаций
python -m ruff check .
python -m pytest -q -m "not browser" --cov --cov-report=term-missing
```

Порог покрытия — 95% (ветви), фактическое — 97%. Порог задан в `pyproject.toml`
(`[tool.coverage.report] fail_under`), поэтому падение покрытия ломает CI, а не
остаётся незамеченным. mypy настроен без требования аннотировать каждую функцию
(`check_untyped_defs`): модель и `D` со свободными атрибутами остаются
динамическими, но опечатки и несовместимые типы в телах находятся.

- Перенос `routing.test.js`: демо, sample, loaded, пустой проект, без серверной,
  1/12 блоков в ряду, исходные 40 проектов (seed 7) и 20 (seed 11).
  LCG воспроизводит **арифметику JS double**, а не иной Python integer RNG.
- Hypothesis: **1000 проектов за запуск**, до 49 блоков, 1–12 в ряду (в том числе
  дробные и текстовые), KVM/RS-485/сигналы/битые цели, произвольные имена и
  заголовки до 60 знаков, числа/строки/мусор в числовых полях, со сжатием
  контрпримеров. Генераторы намеренно включают длинные подписи и большие fan-in:
  именно они вскрывают обрезку подписей и плотность портов.
- Shapely 2 / STRtree: нулевые/диагональные участки, коллинеарное наложение
  >1.5 px (допуск координат 0.05), проход через чужой блок, границы листа,
  стрелки сигналов, внешние связи, легенда и примечания, а также **касание
  концов связи своих блоков**, **слияние портов одной грани** (<0.05 px) и
  **ширина подписей** относительно блока.
- Оптимальность интервального раскрашивания, регрессии портов/коридоров,
  нормализация и round-trip JSON, валидность XML, совпадение текстов/точек
  экспортов, отсутствие мутаций модели, HTTP API и CLI всех четырёх форматов,
  предупреждения модели (обрезка подписей, плотность портов, плохие числа),
  сходимость зазора и охранный порог времени раскладки (300 портов < 2.5 с).

### Автоматические браузерные тесты

Отдельная необязательная зависимость **Playwright для Python**. Не требуется
устанавливать Node.js, npm или собирать приложение. Chromium скачивается один
раз для тестов, не является зависимостью редактора.

```bash
python -m pip install -e ".[test,browser]"
python -m playwright install chromium
# На Linux при отсутствии системных библиотек:
# python -m playwright install --with-deps chromium
python -m pytest tests/browser -q --strict-markers
# Все проверки, включая Hypothesis и браузер:
python -m pytest -q
```

Без extra `browser` браузерный модуль помечается как пропущенный. Если Playwright
установлен, но Chromium отсутствует, запуск браузерных тестов **завершается
ошибкой**, а не создаёт ложное впечатление успешного прогона. Чтобы запустить
только основные проверки, используйте `-m "not browser"`.
Для уже установленного совместимого Chromium можно задать переменную окружения
`SCHEME_BROWSER_EXECUTABLE` с абсолютным путём к исполняемому файлу.

14 браузерных сценариев работают через **настоящий локальный HTTP-сервер** на
свободном порту и отдельный чистый browser context для каждого теста:

- изменение проекта и живого SVG, масштаб и восстановление после reload;
- все четыре вкладки: добавление, редактирование, соединение и удаление элементов,
  KVM-щит, серверные подключения, RS-485 и количества сигналов;
- настоящий диалог выбора файла, JSON round-trip плотного проекта, ошибочные
  импорты без потери текущего проекта;
- реальные скачивания SVG/PNG/JPG/Draw.io с проверкой имён и содержимого файлов;
- отмена и подтверждение сброса, отказ экспорта/превью и последующее восстановление;
- недоступный localStorage и повреждённый сохранённый JSON;
- новое редактирование отменяет предыдущий запрос превью (AbortController), отмена не
  показывается как ошибка и устаревший ответ не перезаписывает более новое редактирование;
- работа редактора при ширине окна 390 px.

Во всех сценариях внешние HTTP-запросы блокируются и считаются ошибкой;
необработанные ошибки JavaScript также проваливают тест. Ожидания основаны на
состоянии интерфейса, ответах API и событиях браузера, без фиксированных sleep.
При падении сохраняются `test-results/<тест>/failure.png`, `page.html` и
`trace.zip` (открыть: `python -m playwright show-trace <путь-к-trace.zip>`).
CI выполняет браузерную группу отдельным Linux job и прикладывает артефакты
при ошибках; основные проверки остаются на Linux/Windows и Python 3.11/3.13.

Исходные `app.js` и `routing.test.js` получены из `Man1nWhite/Structural-Scheme`;
остальные reference-файлы — пользовательские вложения. Лицензия: [LICENSE](LICENSE).
